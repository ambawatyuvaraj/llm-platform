# LLM Inference Platform on Kubernetes

A production-grade LLM inference platform running [TinyLlama](https://huggingface.co/TinyLlama/TinyLlama-1.1B-Chat-v1.0) via [ollama](https://ollama.com) on a self-managed Kubernetes cluster on AWS. Everything ( infrastructure, application, secrets, observability, and deployments ) are automated and version-controlled.

**Live endpoint:** `https://llm-platform.duckdns.org` ( I've destoryed everything to stop aws cost from mounting, so this endpoint isn't accessible anymore.)

---

## What's inside

| Layer | Tools |
|---|---|
| Infrastructure | Terraform, AWS (VPC, EC2, KMS, IAM) |
| Cluster | k3s, Ansible |
| Ingress & TLS | Nginx Ingress, cert-manager, Let's Encrypt |
| Application | ollama, TinyLlama 1.1B |
| Helm chart | Custom chart — HPA, NetworkPolicy, PrometheusRule |
| GitOps | ArgoCD (auto-sync + self-heal) |
| CI/CD | GitHub Actions (lint → Trivy scan → image tag update) |
| Observability | Prometheus, Grafana, Jaeger |
| Secrets | HashiCorp Vault (AWS KMS auto-unseal, sidecar injection) |

## Architecture

```
Internet
    │ HTTPS :443
    ▼
Nginx Ingress (DaemonSet, hostNetwork)
    ├── cert-manager ──► Let's Encrypt TLS
    └── routes to ollama:11434

AWS Region (us-east-1)
├── VPC 10.0.0.0/16 · Public subnet
│   ├── k3s-node-0  (control plane, t3.large)
│   ├── k3s-node-1  (worker, t3.large)
│   └── k3s-node-2  (worker, t3.large)
├── KMS key         (Vault auto-unseal)
├── IAM role        (EC2 → KMS access)
└── Security Groups (22/80/443/6443)

Kubernetes workloads (llm-serving namespace)
└── ollama/TinyLlama pod
    └── vault-agent sidecar (injects HF_TOKEN at runtime)

Observability (monitoring namespace)
├── Prometheus  (scrapes :11434/metrics, SLO alerts)
├── Grafana     (dashboards)
└── Jaeger      (distributed tracing)

GitOps
├── GitHub repo      (charts/vllm, argocd/)
├── GitHub Actions   (helm lint → Trivy → tag update)
└── ArgoCD           (polls repo every 3 min, self-heals)

Secrets
└── HashiCorp Vault
    ├── AWS KMS auto-unseal
    ├── Kubernetes auth (vllm-sa service account)
    └── secret/llm/credentials → HF_TOKEN injected into pod
```

## Prerequisites

- **AWS account** — upgraded to Pay-As-You-Go (free tier blocks t3.large instances)
- **Terraform Cloud account** — free tier works, used for remote state
- **GitHub account** — repo and GitHub Actions
- **DuckDNS account** — free dynamic DNS at [duckdns.org](https://www.duckdns.org), create a subdomain first
- **HuggingFace account** — read token for Vault secrets demo

Install required tools on Fedora/Linux (I use Fedora , but it's pretty straightforward for other distros too.):

```bash
sudo dnf install -y awscli2 ansible git python3 openssl nc

# Terraform
sudo dnf install -y dnf-plugins-core
sudo dnf config-manager --add-repo https://rpm.releases.hashicorp.com/fedora/hashicorp.repo
sudo dnf install -y terraform vault

# kubectl
curl -LO "https://dl.k8s.io/release/$(curl -sL https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
chmod +x kubectl && sudo mv kubectl /usr/local/bin/

# Helm
curl https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash
```

## One-time setup

### 1. AWS IAM user

Create an IAM user in AWS and attach this policy:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    { "Sid": "EC2Full",         "Effect": "Allow", "Action": ["ec2:*"], "Resource": "*" },
    { "Sid": "KMSFull",         "Effect": "Allow", "Action": ["kms:*"], "Resource": "*" },
    { "Sid": "S3Full",          "Effect": "Allow", "Action": ["s3:*"],  "Resource": "*" },
    { "Sid": "IAMForTerraform", "Effect": "Allow", "Action": [
        "iam:CreateRole", "iam:DeleteRole", "iam:AttachRolePolicy", "iam:DetachRolePolicy",
        "iam:PutRolePolicy", "iam:DeleteRolePolicy", "iam:GetRole", "iam:GetRolePolicy",
        "iam:ListRolePolicies", "iam:ListAttachedRolePolicies",
        "iam:TagRole", "iam:UntagRole",
        "iam:CreateInstanceProfile", "iam:DeleteInstanceProfile",
        "iam:AddRoleToInstanceProfile", "iam:RemoveRoleFromInstanceProfile",
        "iam:GetInstanceProfile", "iam:PassRole"
    ], "Resource": "*" }
  ]
}
```

```bash
aws configure --profile terraform
# Enter Access Key ID, Secret, region: us-east-1, format: json

aws sts get-caller-identity --profile terraform   # verify it works
```

### 2. Terraform Cloud workspace

Create a free org and workspace called `llm-platform` at [app.terraform.io](https://app.terraform.io). Set execution mode to **Remote**. Add these environment variables in workspace settings:

```
AWS_ACCESS_KEY_ID      = AKIA...      (Sensitive)
AWS_SECRET_ACCESS_KEY  = ...          (Sensitive)
AWS_DEFAULT_REGION     = us-east-1
TF_VAR_my_ip_cidr      = your.ip/32
```

```bash
terraform login
```

### 3. SSH key

```bash
ssh-keygen -t ed25519 -f ~/.ssh/k3s_ed25519 -N "" -C "k3s-cluster"

aws ec2 import-key-pair \
  --key-name "k3s-key" \
  --public-key-material fileb://~/.ssh/k3s_ed25519.pub \
  --region us-east-1
```

### 4. Shell aliases

Add to `~/.zshrc` (update `CONTROL_PLANE_IP` after first Terraform apply):

```bash
alias p1-up='cd ~/Desktop/terraform_projects/llm_project/terraform && terraform apply -auto-approve'
alias p1-dn='cd ~/Desktop/terraform_projects/llm_project/terraform && terraform destroy -auto-approve'
alias k3s-tunnel='ssh -i ~/.ssh/k3s_ed25519 -L 6443:localhost:6443 ubuntu@CONTROL_PLANE_IP -N -f'
alias k3s-tunnel-kill='pkill -f "L 6443:localhost:6443"'
```

> **Every session:** run `k3s-tunnel` before any `kubectl` or `helm` command. Port 6443 is blocked by most ISPs — kubectl talks to the cluster through an SSH tunnel.

## Deploying the stack

### Step 1 — Provision AWS infrastructure

```bash
cd terraform/
terraform init
terraform plan    # 23 resources to create
terraform apply
```

Creates: VPC, 3× t3.large EC2 (Ubuntu 22.04), KMS key, IAM instance profile, security groups. After apply, note the output IPs.

> t3.medium (4GB) is not enough. ollama needs at least 8GB RAM — use t3.large.

### Step 2 — Install k3s cluster

```bash
# Generate inventory from Terraform outputs
chmod +x scripts/generate-inventory.sh
./scripts/generate-inventory.sh

# Run Ansible (~5-8 minutes)
cd ansible/
ansible-playbook -i inventory.ini playbook.yml
```

Workers join the control plane via private IP (`10.0.1.x`) — the security group only allows port 6443 from within the VPC, not from the public internet.

### Step 3 — Configure kubectl

```bash
CTRL=$(cd ../terraform && terraform output -raw control_plane_ip)

scp -i ~/.ssh/k3s_ed25519 ubuntu@${CTRL}:/etc/rancher/k3s/k3s.yaml /tmp/k3s.yaml
mkdir -p ~/.kube && cp /tmp/k3s.yaml ~/.kube/config
sed -i "s|server: https://127.0.0.1:6443|server: https://localhost:6443|g" ~/.kube/config
chmod 600 ~/.kube/config

# Update tunnel alias with new IP
sed -i "s|ubuntu@[0-9.]*|ubuntu@${CTRL}|g" ~/.zshrc && source ~/.zshrc

k3s-tunnel && sleep 3
kubectl get nodes   # 3 nodes: Ready
```

### Step 4 — Nginx Ingress + cert-manager + TLS

```bash
helm repo add ingress-nginx https://kubernetes.github.io/ingress-nginx
helm repo add jetstack https://charts.jetstack.io
helm repo update

helm upgrade --install ingress-nginx ingress-nginx/ingress-nginx \
  --namespace ingress-nginx --create-namespace \
  --set controller.hostNetwork=true \
  --set controller.kind=DaemonSet \
  --set controller.daemonset.useHostPort=true \
  --set controller.config.use-forwarded-headers="true"

helm upgrade --install cert-manager jetstack/cert-manager \
  --namespace cert-manager --create-namespace \
  --set installCRDs=true

kubectl rollout status deployment/cert-manager-webhook -n cert-manager --timeout=120s
```

Set security headers globally (avoids `configuration-snippet` which is disabled in nginx ≥v1.9 and causes the fake self-signed cert issue):

```bash
kubectl apply -f - << 'EOF'
apiVersion: v1
kind: ConfigMap
metadata:
  name: custom-headers
  namespace: ingress-nginx
data:
  Strict-Transport-Security: "max-age=31536000; includeSubDomains"
  X-Content-Type-Options: "nosniff"
  X-Frame-Options: "DENY"
  X-XSS-Protection: "1; mode=block"
  Referrer-Policy: "strict-origin-when-cross-origin"
EOF

kubectl patch configmap ingress-nginx-controller -n ingress-nginx \
  --patch '{"data":{"add-headers":"ingress-nginx/custom-headers"}}'
```

Apply the ClusterIssuer (update email):

```bash
kubectl apply -f - << 'EOF'
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: letsencrypt-prod
spec:
  acme:
    server: https://acme-v02.api.letsencrypt.org/directory
    email: your-email@gmail.com
    privateKeySecretRef:
      name: letsencrypt-prod-key
    solvers:
    - http01:
        ingress:
          class: nginx
EOF
```

Update DuckDNS to point at your new control plane IP:

```bash
CTRL=$(cd terraform && terraform output -raw control_plane_ip)
curl -s "https://www.duckdns.org/update?domains=YOUR_SUBDOMAIN&token=YOUR_TOKEN&ip=${CTRL}"
```

### Step 5 — Deploy ollama / TinyLlama

```bash
kubectl create namespace llm-serving 2>/dev/null || true
kubectl label namespace llm-serving  kubernetes.io/metadata.name=llm-serving  --overwrite
kubectl label namespace ingress-nginx kubernetes.io/metadata.name=ingress-nginx --overwrite
kubectl label namespace cert-manager  kubernetes.io/metadata.name=cert-manager  --overwrite
kubectl create serviceaccount vllm-sa -n llm-serving 2>/dev/null || true

# Delete the admission webhook if it causes timeout errors
kubectl delete validatingwebhookconfiguration ingress-nginx-admission 2>/dev/null || true

helm upgrade --install vllm charts/vllm/ \
  --namespace llm-serving \
  --set prometheusRule.enabled=false \
  --set networkPolicy.enabled=false \
  --wait --timeout 30m
```

Watch the pod come up:

```bash
kubectl get pods -n llm-serving -w
# Init:0/1 → PodInitializing → Running → 1/1 Ready
```

The `pull-model` initContainer downloads TinyLlama (~637MB) before the main container starts. On first run this takes a few minutes.

Test:

```bash
curl https://llm-platform.duckdns.org/api/tags
curl https://llm-platform.duckdns.org/api/generate -d '{
  "model": "tinyllama",
  "prompt": "What is Kubernetes in one sentence?",
  "stream": false
}'
```

### Step 6 — GitOps with ArgoCD

Push your code to GitHub first, then install ArgoCD:

```bash
echo ".argocd-password" >> .gitignore
gh repo create llm-platform --public --source=. --remote=origin --push

kubectl create namespace argocd
kubectl apply -n argocd \
  -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml

kubectl wait --for=condition=available deployment/argocd-server -n argocd --timeout=300s

ARGOCD_PASS=$(kubectl -n argocd get secret argocd-initial-admin-secret \
  -o jsonpath="{.data.password}" | base64 -d)
echo "$ARGOCD_PASS" > .argocd-password && chmod 600 .argocd-password
```

Update `argocd/application.yaml` with your GitHub username, then apply:

```bash
kubectl apply -f argocd/application.yaml
kubectl get application vllm-platform -n argocd
# SYNC STATUS: Synced   HEALTH STATUS: Healthy
```

From this point on — push to git, ArgoCD deploys it. No more manual `helm upgrade`.

The GitHub Actions pipeline runs on every push:
1. `helm lint` + `kubectl dry-run` — validates the chart
2. Trivy security scan — checks rendered manifests for misconfigurations
3. Image tag update — commits the new tag to `values.yaml` with `[skip ci]`

### Step 7 — Observability

```bash
GRAFANA_PASS=$(cat .grafana-password 2>/dev/null || \
  openssl rand -base64 24 | tr -dc 'A-Za-z0-9' | head -c 32)
echo "$GRAFANA_PASS" > .grafana-password && chmod 600 .grafana-password

kubectl create namespace monitoring
kubectl label namespace monitoring kubernetes.io/metadata.name=monitoring --overwrite

kubectl create secret generic grafana-admin-credentials \
  --from-literal=admin-user=admin \
  --from-literal=admin-password="$GRAFANA_PASS" \
  -n monitoring

helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm upgrade --install kube-prometheus-stack \
  prometheus-community/kube-prometheus-stack \
  --namespace monitoring \
  --set grafana.admin.existingSecret=grafana-admin-credentials \
  --set grafana.admin.userKey=admin-user \
  --set grafana.admin.passwordKey=admin-password

helm repo add jaegertracing https://jaegertracing.github.io/helm-charts
helm upgrade --install jaeger jaegertracing/jaeger \
  --namespace monitoring \
  --set allInOne.enabled=true \
  --set storage.type=memory \
  --set allInOne.resources.requests.memory=256Mi \
  --set allInOne.resources.limits.memory=512Mi
```

Access the UIs:

```bash
kubectl port-forward svc/kube-prometheus-stack-grafana -n monitoring 3000:80 &
# http://localhost:3000  (admin / contents of .grafana-password)

kubectl port-forward svc/jaeger -n monitoring 16686:16686 &
# http://localhost:16686
```

Enable SLO alerts by committing this to `charts/vllm/values.yaml`:

```yaml
prometheusRule:
  enabled: true
```

ArgoCD picks it up automatically — no manual deploy needed.

### Step 8 — HashiCorp Vault

The KMS key and IAM role were already provisioned in Step 1. This step installs Vault, initialises it, and configures secret injection.

```bash
KMS_KEY_ID=$(cd terraform/ && terraform output -raw vault_kms_key_id)

cat > vault-values.yaml << EOF
server:
  dev:
    enabled: false
  ha:
    enabled: false
  dataStorage:
    enabled: true
    size: 1Gi
    storageClass: local-path
  seal:
    type: awskms
    config:
      region: "us-east-1"
      kms_key_id: "${KMS_KEY_ID}"
  affinity: ""
injector:
  enabled: true
EOF

helm repo add hashicorp https://helm.releases.hashicorp.com
kubectl create namespace vault 2>/dev/null || true
kubectl label namespace vault kubernetes.io/metadata.name=vault --overwrite

helm install vault hashicorp/vault \
  --namespace vault \
  --values vault-values.yaml
```

Initialise and unseal:

```bash
kubectl exec -n vault vault-0 -- \
  vault operator init -key-shares=5 -key-threshold=3 -format=json > vault-init.json
chmod 600 vault-init.json

ROOT_TOKEN=$(cat vault-init.json | python3 -c \
  "import json,sys; print(json.load(sys.stdin)['root_token'])")
echo "$ROOT_TOKEN" > .vault-root-token && chmod 600 .vault-root-token

for i in 0 1 2; do
  KEY=$(cat vault-init.json | python3 -c \
    "import json,sys; print(json.load(sys.stdin)['unseal_keys_b64'][$i])")
  kubectl exec -n vault vault-0 -- vault operator unseal "$KEY"
done
```

Configure Vault and store the HuggingFace token:

```bash
export HF_TOKEN="hf_your_token_here"   # from huggingface.co/settings/tokens
./scripts/configure-vault.sh
```

Commit the Vault annotations to `charts/vllm/templates/deployment.yaml` and push — ArgoCD restarts the pods with the vault-agent sidecar. Pods should show `2/2 Ready`.

## Reprovisioning

Destroy and rebuild the entire stack:

```bash

./scripts/reprovision.sh               # rebuild from scratch
```

`reprovision.sh` runs all steps automatically: Terraform → Ansible → kubectl → all Helm installs → Vault init → configure-vault.

## Common issues

| Error | Cause | Fix |
|---|---|---|
| `connection refused localhost:6443` | SSH tunnel not running | Run `k3s-tunnel` before kubectl |
| `502 Bad Gateway` | NetworkPolicy blocking nginx | Run `kubectl delete networkpolicy -n llm-serving --all` |
| Vault `permission denied` on k8s login | `K8S_HOST` set to tunnel address | Use `https://kubernetes.default.svc` in configure-vault.sh |
| `SSL: self-signed certificate` | `configuration-snippet` in ingress.yaml | Remove the annotation — disabled in nginx ≥v1.9 |
| Pod `Exit Code 137` | OOM killed | Requires t3.large (8GB). t3.medium not enough for ollama |
| ArgoCD creates duplicate deployment | Missing `releaseName: vllm` | Add `releaseName: vllm` under `spec.source.helm` in application.yaml |
| Vault sealed after reprovision | KMS auto-unseal needs IAM profile | Verify IAM instance profile is attached to EC2 at launch |
| `helm: context deadline exceeded` | Old admission webhook certificate | `kubectl delete validatingwebhookconfiguration ingress-nginx-admission` |

## Security

- All secrets are gitignored: `vault-init.json`, `.vault-root-token`, `.argocd-password`, `.grafana-password`, `vault-values.yaml`, `ansible/inventory.ini`
- IAM uses least-privilege policy with named Sids
- SSH restricted to your IP only (port 22), TLS on all public endpoints
- Security headers set globally in nginx ConfigMap (HSTS, X-Frame-Options, CSP)
- Containers run as uid=1000, non-root, `capabilities.drop: ALL`, `seccompProfile: RuntimeDefault`
- Secrets injected at runtime by Vault Agent sidecar — never baked into images or ConfigMaps
